# Security policy

## Reporting a security issue

Please report suspected vulnerabilities privately to **security@halveth.de**. Include the affected repository or service, a concise description, the smallest safe reproduction, the observed impact, and the relevant revision. Remove secrets and personal data; do not attach credentials, session tokens, private keys, or unrelated user data.

This address is a reporting route. It does not promise a response time, acceptance, safe harbor, payment, compensation, or a bug-bounty reward. This repository does not currently operate a public bug-bounty program.

## Scope and testing

A public repository, public website, or successful report does not by itself authorize active testing. Test only assets for which you have current, explicit authorization and a defined scope. Follow the named program or written authorization, including allowed methods, exclusions, rate limits, time window, data rules, and stop conditions.

Do not bypass authentication, access controls, rate limits, or platform protections; access other users' data; test across tenants; harvest credentials; exfiltrate data; use social engineering; or cause denial of service, persistence, destruction, or material service impact. Stop if sensitive data appears, the service behaves unexpectedly, or the authorized scope is unclear.

For coordinated disclosure, keep the report private until the affected maintainer and reporter agree on a disclosure plan or an applicable policy sets one. Do not open a public issue containing an unpatched vulnerability.

This policy covers code and workflows maintained in this repository. Linked repositories, GitHub itself, external dependencies, and third-party services keep their own security policies and authorization requirements.
